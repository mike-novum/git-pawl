# GUI для работы с гит и удаленными репозиториями

Разрабатываем GUI-приложенеи для MacOS для работы с Git.

## Стек

- React
- Typescript
- Electron (основной фреймворк для десктопа https://www.electronjs.org/docs/latest/) 
- Vite (в сети имеется готовый шаблон с Electron https://electron-vite.github.io/)
- EsLint 9 для линтинга кода
- Storybook для UI-кит из которого будем собирать интерфейс
- Shadcn (Base UI) для UI-кит


## Функционал который хочется

- клонирование репозиториев по ссылке
- авторизации в Gilab, GitHub аккаунтах с возможностью подключать несколько аккаунтов с последующей возможностью выбирать какие репозитории склонировать из доступных аккаунтов
- базовые инструменты для работы с репозиторием (pull push commit stash patch merge rebase reset revert amend и тп)
- создание патчей
- создание/удаление гит-тегов
- конфигурация пользователя (глобавльная и под каждый репозиторий)
- предпросмотр изменений + отметки файлов через чекбоксами какие отправить в коммит
- отображение графа коммитов с авторами сообщениями коммитов и датами в хронологичном порядке по времени
- создание рабочих пространств (пользователь выбирает или создает директорию на диске компьютера и потом в рамках этого пространства клонирует нужные репозитории)
- понятный редактор сообщений к коммитам с возможностью отдельно указывать header body footer коммита (раздельные поля)
- возможность отключать precommit хуки (bypass hooks)
- возможность задавать иконки репозиториям (выбранная картинка должна появиться в корне проекта как файл icon.png или icon.jpg и потом подтягиваться интерфейсом) для визуального удобства
- поиск по репозиториям
- подсказка суммарного размера файлов в локальной папке репозитория


## Технические детали

- весь UI-кит вынести в src/shared/ui
- должны быть описаны семантические токены дизайн-системы в отдельных файлах для светлой и темной темы (вот этот момент с токенами надо пробрейнштормить реально ли вообще в Tailwind так сделать или лучше все делать через что то другое)
- по умолчанию темная тема включена должна быть
- основной цвет делаем оранжевый
- надо сделать иконку приложения с лапой кота (оранжевая лапа в сметане)
- у интерфейса допускаются легкие быстрые плавные анимации чтобы интерфейс не был слишком резким (но не через чур медленными, анимации не должны сильно тормозить пользователя)

2. Собираем простоый UI-кит

3. Отправляемся делать всю бизнеслогику по очереди (предварительно расширяя UI кит если требуются какие то еще компоненты)
