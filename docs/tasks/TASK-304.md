# TASK-304 — переделать граф коммитов на нормальное дерево (ветки/теги/сообщения)

## Доработка
На странице репозитория (`src/pages/repository/ui/RepositoryPage.tsx`) граф коммитов сейчас выглядит как обычный список кнопок с маленькой иконкой слева (`src/widgets/repo-graph-vertical/ui/RepoGraph.tsx`):
```
● abc1234 Some commit
  Author · 2h ago
● def5678 Another commit
  Author · 1d ago
```
Это плохо читается, не показывает ветки/теги и не похоже на нормальный git-граф.

Нужно сделать настоящий визуальный граф с lanes (дорожками), линиями между коммитами, ветками и тегами — как в SourceTree / GitKraken.

## Что сделать

### Шаг 1. Использовать данные
1. Данные о коммитах берутся из `gitLog` (уже есть в `RepositoryPage`).
2. Данные о ветках (`useBranches(repoPath)`) и тегах (`useTags(repoPath)`) уже есть.
3. Данные о lane/parent есть в `CommitNode` (поле `parents: string[]`).

### Шаг 2. Переработать layout графа
1. Открыть `src/widgets/repo-graph-vertical/ui/RepoGraph.tsx` (или переименовать/расширить виджет).
2. Layout:
   - SVG слева: lanes с линиями (как уже есть в `src/widgets/commit-graph/ui/CommitGraph.tsx`), но адаптированный под вертикальный список коммитов.
   - Справа — текстовый блок: `shortHash` (mono), `subject` (truncate), branch/tag chips, `author · relativeTime`.
3. Для каждого коммита определить, в каких ветках/тегах он находится (через `useBranches`/`useTags` — у каждой ветки/тега есть `target` hash). Показывать чипы рядом с сообщением.
4. Цвет lane: использовать `--color-primary` для активной ветки, `--color-muted-foreground` для остальных.
5. Линии: рисовать SVG `<path>` от каждого коммита к его `parents` через lane-центры (с правильными углами/скруглениями).

### Шаг 3. Стили
1. Высота строки — `~44px` (чуть меньше текущих 32px-высоты svg + контента, но достаточно для двух строк текста).
2. Лес длинных линий не должен тормозить — использовать простые `<path d="M ... L ...">` без фильтров.
3. Hover: подсветить строку + lane (через CSS, не пересчитывая layout).

### Шаг 4. Адаптивность
1. На узких экранах скрывать `author` и `relativeTime`, оставлять только `shortHash` + `subject`.
2. Branch/tag chips всегда видны (через overflow tooltip, если не влезают).

## Acceptance criteria
- [x] Граф визуально выглядит как дерево коммитов с ветками (lanes), а не как список с иконкой.
- [x] Видны ветки (например, `main`, `feature/x`) и теги рядом с сообщением коммита, в котором они указывают.
- [x] Линии между коммитами корректно проходят через дорожки (при merge commit линии сходятся к одному родителю).
- [x] Клик по коммиту по-прежнему выделяет его и триггерит `onSelect`.
- [x] На репозитории с >50 коммитов рендер остаётся плавным (нет явных лагов).
- [x] `npm run tsc` + `eslint` проходят без ошибок.
