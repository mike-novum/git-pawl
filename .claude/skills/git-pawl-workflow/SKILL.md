# git-pawl Subagent Workflow

Этот skill ОБЯЗАН прочитать любой сабагент, начинающий работу над `git-pawl`.

## 1. Где брать задачи

Все задачи лежат в **`docs/tasks/`**. Каждая — отдельный файл `TASK-NNN-*.md`.

Список и зависимости — в `docs/tasks/README.md`.

Перед стартом:
1. Открой свой файл `docs/tasks/TASK-NNN-*.md`.
2. Прочитай `docs/architecture/architecture.md` — это источник истины по слоям FSD, IPC-контрактам и соглашениям.
3. Прочитай `AGENTS.md` — кодовый стиль (стрелочные функции, FC, типы в `types.ts`, no comments).
4. Прочитай оба FSD-скилла:
   - `.claude/skills/fsd-core/SKILL.md` — слои и импорты.
   - `.claude/skills/fsd-segments/SKILL.md` — структура сегментов.

## 2. Когда можно начинать

- Задача помечена `⏳ pending` в `docs/tasks/README.md` (или это новая).
- Все зависимости (колонка «Зависит от») уже имеют статус ✅.
- Если зависимость не закрыта — СТОП, сообщи main-агенту, что нужно сначала закрыть зависимость.

## 3. Как работать

1. Поставь задачу в `🔧 in_progress` в `docs/tasks/README.md` (замени ⏳ на 🔧 для строки своей задачи).
2. Реализуй ровно то, что написано в твоём TASK-файле. Не выходи за scope.
3. Соблюдай FSD:
   - новый код в правильный слой/слайс/сегмент
   - импорты только из нижестоящих слоёв
   - public API через `index.ts`
4. Соблюдай стиль (AGENTS.md):
   - стрелочные функции для функций
   - `const Component: FC<Props> = () => {...}` для компонентов React
   - типы выноси в `types.ts` рядом с `Component.tsx`
   - не добавляй комментариев (если не попросят)
   - eslint clean: `npm run lint:fix <files>` для своих файлов
   - tsc clean: `npm run tsc` для всего проекта
5. Используй UI-кит из `src/shared/ui` (после TASK-002..004). Никаких ad-hoc кнопок или inputs.

## 4. Как верифицировать

Перед тем как сказать «готово», ОБЯЗАТЕЛЬНО проверь:

- [ ] Файлы, которые ты создал/изменил, проходят `npx tsc --noEmit`.
- [ ] Файлы проходят `npx eslint <files>` без ошибок (используй `--fix` где можно).
- [ ] Если есть тесты — `npm test` для своих компонентов.
- [ ] Если UI — посмотри в Storybook, проверь визуально (если возможно).
- [ ] Если фича — happy path и один edge case прогнаны.

## 5. Как сообщать о готовности

В конце своей TASK-NNN.md добавь:

```markdown
## Статус: DONE — <короткая сводка>

### Что сделано
- <bullet 1>
- <bullet 2>

### Acceptance criteria (отметить выполненные)
- [x] ...
- [x] ...

### Заметки для ревьюера
- <если есть нюансы>
```

Также обнови строку в `docs/tasks/README.md`:
- ⏳ → ✅
- Или ⏳ → 🔧 → ✅

Кратко сообщи main-агенту:
- TASK-NNN готово.
- Какие файлы созданы/изменены.
- Нужен ли ревьюер (см. ниже).

## 6. Code review

Main-агент по умолчанию запускает отдельного сабагента-ревьюера для каждой завершённой задачи.

Если main-агент не сделал этого явно, всё равно в финальном сообщении укажи: «требуется ревью для TASK-NNN».

Ревьюер проверяет:
- Соответствие AGENTS.md (стиль, FSD).
- Корректность типов.
- Edge cases.
- Дублирование кода.
- Размер компонентов/файлов.

## 7. Анти-паттерны (НЕ делать)

- ❌ Добавлять код в слой, отличный от указанного в задаче.
- ❌ Писать прямые импорты, обходя public API слайса (`@/features/foo/ui/Foo` вместо `@/features/foo`).
- ❌ Использовать `function` (только стрелочные функции).
- ❌ Использовать `enum` (только literal types).
- ❌ Добавлять комментарии без запроса.
- ❌ Слишком длинные названия файлов/функций (>5 слов).
- ❌ Закрывать задачу без `npm run tsc` + `eslint`.
- ❌ Игнорировать зависимости.

## 8. Частые подсказки

- Не нашёл нужный UI-кит-компонент? Проверь, может TASK-002..004 уже создали его. Если нет — добавь как отдельную подзадачу и не делай ad-hoc.
- Не знаешь, в какой слой положить? Смотри `docs/architecture/architecture.md` раздел 3 (Слои FSD).
- IPC не работает? Проверь, что preload экспонирует канал и zod-схема валидна.
- Темы не применяются? Проверь атрибут `data-theme` на `<html>` и значения токенов в `src/app/styles/theme.css`.

## 9. Чеклист перед завершением

- [ ] Прочёл свою задачу + архитектуру + правила.
- [ ] Положил код в правильные слои.
- [ ] Стиль соответствует AGENTS.md.
- [ ] `npm run tsc` — без ошибок.
- [ ] ESLint по моим файлам — без ошибок.
- [ ] Если применимо — Storybook-история добавлена.
- [ ] Если применимо — юнит-тест добавлен.
- [ ] TASK-NNN.md обновлён (статус DONE).
- [ ] README обновлён (⏳ → ✅).
- [ ] Сообщил main-агенту.
