# Импорты между сегментами слайса

По текущим правилам строй связи 
 
`/api` - может использовать внутри себя `lib`, `config`, `model`
`/lib` - не зависит от других сегментов
`/model` - не зависит от других сегментов
`/ui` - может использовать внутри себя  `lib`, `config`, `model`, `api`
`/config` - не зависит от других сегментов


# Иерархия директорий и файлов внутри сегментов

Внутри сегментов допускается создание своей иерархии для группировки кода под назначению.

При выборе той или иной иерархии директорий нужно свести направление связей между ними в одну сторону чтобы исключить появление циклических зависимостей.

Дополнительная иерархия сегментов требуется в случае если у вас появляется слишком много файлов разного назначения, например UI компоненты и общие типы для этих UI компонентов следует разнести по файлам `ui/components` и `ui/types`.

## api

`/api/mappers` - мапперы данных
`/api/params` - утилиты для работы с query-параметрами браузерной строки 
`/api/models` - утилиты для типизации 
`/api/queries` - утилиты  использующие Tanstack для получения данных
`/api/mutations` - утилиты использующие Tanstack для мутаций данных


## ui

`ui/components`
`ui/types`
`ui/utils` 

## model

`/model/domain`
`/model/stores`
`/model/schemas`


## lib

`/lib/{название-локальной-библиотеки}` - библиотечный код группировать в директории по названию локальной библиотеки
